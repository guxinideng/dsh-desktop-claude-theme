## 你要解决的核心问题

用户把这个应用添加到 iPhone 主屏当独立应用用。**独立应用没有地址栏、没有后退按钮、没有加载进度条**——桌面网页能靠浏览器 chrome 兜底的东西,这里一样都没有。

现在的情况是:点开图标 → 一片纯白 → 若干秒后界面突然出现。中间没有任何东西告诉用户"它在动"。你这 7 项里有 4 项都在解决这个。

## 任务 1:首屏骨架屏(优先级最高)

### 现状证据

服务端返回的 HTML 里,应用挂载点是完全空的:

```
root 内部内容长度: 0
含 loading/skeleton 标记: False
DOM 解析完成: 111ms
资源加载完成: 656ms
首次内容绘制: 3328ms   ← 中间 2.7 秒白屏
```

dsh 是 SPA,HTML 到达后还要下载 JS(vendor 744KB + index 442KB)、解析执行、React 挂载、拉数据,才能画出第一个像素。

### 要做什么

在 `serveThemedIndex()` 注入 HTML 时,往空的 `<div id="root"></div>` 里塞一段**静态骨架**。React 挂载时会自然把它替换掉,不需要任何清理逻辑,也不需要前端配合。

骨架内容建议贴合真实布局(页头一条 + 中间留白 + 底部输入框轮廓),配一个低调的呼吸/微光动画表示"在加载"。样式**内联写在骨架里**,不要依赖 mobile.css——它是另一个文件、另一个人在改,而且骨架必须在 CSS 加载完之前就能显示。

### 注意

- 骨架的配色要跟应用一致(暖白底 `#FAF9F5` 系),否则会看到骨架和真实界面之间的突兀切换
- 深色模式:用户当前是锁定浅色的(mobile.js 里有 `pinMobileToLight`),骨架跟着浅色走就行
- 别做得太花哨,它只存在一两秒

### 验收

用 Browser pane 打开测试网关,在 JS 完全执行前应该能看到骨架。可以用 `curl` 直接看返回的 HTML 里 `#root` 是否已经有内容:

```bash
curl -s http://127.0.0.1:3098/ | python3 -c "
import re,sys
h=sys.stdin.read()
m=re.search(r'<div id=\"root\"[^>]*>(.*?)</div>', h, re.S)
print('root 内容长度:', len(m.group(1).strip()) if m else '未找到')
"
```

## 任务 2:冷启动唤醒页

### 现状证据

`ensureDshReady()`(第 145 行)在 dsh 没运行时会拉起它,然后**阻塞等待最长 30 秒**:

```js
const deadline = Date.now() + 30000;
while (Date.now() < deadline) { ... }
```

这期间 HTTP 请求一直挂着不返回。手机上就是白屏 + 转圈,没有任何说明。

### 要做什么

检测到 dsh 未就绪时,**立即返回一个 HTML 页面**(不要挂起请求),页面上说明"正在唤醒,大约需要 X 秒",并自动轮询/重试,就绪后自动跳转到真实应用。

关键点:**先给反馈,再等待**,而不是让用户对着白屏猜。

### 背景

这一页在项目早期设计过("冷启动唤醒中"页),做过原型但一直没接进网关。不是新需求,是补上缺失的部分。

### 注意

- 只有导航请求(`Accept: text/html` 的 GET `/`)才返回这个页面;API 请求、资源请求不能被这个页面污染
- 自动重试要有上限,不要无限轮询
- 如果最终失败,转到任务 3 的错误页

## 任务 3:错误页 HTML 化

### 现状证据

网关的失败分支返回的都是裸文本:

```js
res.writeHead(504, { 'content-type': 'text/plain; charset=utf-8' });
res.end('dsh 启动超时，请重试');

res.writeHead(502, ...);
res.end('dsh 暂时不可用，请稍后重试');
```

在全屏独立应用里,这呈现为左上角一行没有任何样式的小黑字。

### 要做什么

换成有样式的 HTML 页面:说明发生了什么、可能的原因、一个明显的"重试"按钮。

### 为什么重要

桌面上遇到这种页面还能靠地址栏刷新或后退键;独立应用**没有地址栏也没有后退按钮**,这一行字就是死胡同,用户只能强杀应用重开。

## 任务 4:PWA meta 补全

### 现状证据

```
apple-mobile-web-app-capable          缺失
apple-mobile-web-app-status-bar-style 缺失
apple-mobile-web-app-title            缺失
apple-touch-icon                      缺失
```

HTML 里一个 apple 前缀的 PWA 标签都没有。

### 要做什么

在 `serveThemedIndex()` 注入 `</head>` 时补上这几个标签。iOS 主要认这些 apple 前缀标签,manifest 的支持是后来才加的、覆盖有限。

- `apple-mobile-web-app-title` 建议用简短的中文名(主屏图标下显示的字)
- `apple-mobile-web-app-status-bar-style` 要跟应用配色协调(浅色主题用 `default`)
- apple-touch-icon 需要一个 PNG(iOS 对 SVG 图标支持有限)。当前 manifest 里只有一个 SVG favicon。如果项目里没有合适的 PNG,**先报告再决定**,不要自己生成一个凑数

## 任务 5:manifest 修正

### 现状证据

```json
{ "display": "fullscreen", ... }
```

`fullscreen` 会隐藏状态栏(时间、电量、信号)。对一个随时进出的聊天工具,这个损失明显,`standalone` 才是这类应用的常规选择。

### 要做什么

manifest 是 dsh 提供的、经网关代理出去的。需要在网关拦截 `/manifest.webmanifest` 的响应并改写 `display` 字段。

### 注意

用户之前发的截图里状态栏是可见的,说明 iOS 可能已经忽略了这个声明、按 standalone 处理。所以这条**优先级低**,价值主要在"配置和实际表现对齐"。如果改起来麻烦,可以先报告再定。

## 任务 6:启动画面

独立应用启动时,从点图标到界面出现之间是系统默认白屏。配上 splash 后能和任务 1 的骨架屏在视觉上接起来,形成连贯的启动过程。

iOS 的 splash 配置比较繁琐(需要针对不同屏幕尺寸提供图片)。**先评估成本再决定做到什么程度**,如果需要生成大量图片资源,先报告。

## 任务 7:异步读盘

### 现状证据

```js
res.end(fs.readFileSync(asset.file, 'utf8'));   // 第 317 行
```

`mobile.js` 93KB + `mobile.css` 54KB,每次请求同步读盘。Node 单线程,同步读盘期间整个进程停摆——包括正在进行的 WebSocket 消息和语音上传。

### 要做什么

改成异步读取 + 内存缓存(按文件 mtime 判断是否需要重读,这样既避免重复读盘,又保留"改了文件立即生效"的开发体验)。

### 优先级说明

VPS 那层已经缓存了一小时,这些请求很少真正打到网关。属于"结构上不对但当前影响有限",放最后做。
