# 共同须知(三份工作单都先读这个)

## 这个项目是什么

`dsh-desktop-claude-theme` 是给 DeepSeek Harness(`dsh`,一个本地 AI 编程工具,自带网页界面,监听 `127.0.0.1:3080`)做的**第三方外壳 + 主题**。

**核心约束:不 fork、不改 dsh 本身。** dsh 每次发版前端类名都是构建时哈希、会变,所以一切都靠"外挂"手段实现:

- `theme.css` / `mobile.css` — CSS 覆盖
- `mobile.js` — 运行时 DOM 脚本
- `remote-gateway.js` — 反向代理,负责把上面三个文件注入到 dsh 返回的 HTML 里

手机访问链路:

```
手机 → VPS(nginx, 公网入口) → SSH 反向隧道 → Mac 上的 remote-gateway.js(:3090) → dsh(:3080)
```

用户是把它**从 Safari 添加到主屏、当独立应用用的**(不是在浏览器标签页里)。这点很关键:没有地址栏、没有后退按钮、没有加载进度条。

## 为什么有这批任务

整个移动端是从桌面网页改造来的,很多交互还是"鼠标思维"。做了一次系统走查,找出 13 个问题,按文件切成三份并行做。

## 铁律:文件独占

**今天已经出现两次两个会话同时改同一个文件、commit 互相夹带的事故。** 所以:

| 谁 | 只能改 |
|---|---|
| Sonnet 5 | `remote-gateway.js` |
| Opus 5 | `mobile.js` |
| DeepSeek V4-Flash | `mobile.css` |

- **只 `git add` 你自己那个文件**,禁止 `git add .` / `git add -A`
- 发现任务需要改别人的文件 → **停下来报告**,不要动
- 每次 Edit 前先重新 Read 一遍(别人可能刚改过同目录其它文件)
- 用 Edit 局部替换,不要用 Write 整篇重写

## 怎么验证(不要跳过)

### 起一个独立的临时网关,不要碰正式的

正式网关(端口 3090)是用户手机正在连的,**不要动它**。测试用独立端口:

```bash
cd /Users/secondcomputer/Documents/Claude/Projects/dsh-desktop-claude-theme
(GATEWAY_PORT=3098 nohup node remote-gateway.js > /tmp/gw-test.log 2>&1 &)
sleep 2 && curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:3098/
```

测完关掉:

```bash
lsof -ti :3098 | xargs -r kill
```

### 关键坑:改了 remote-gateway.js 必须重启进程

Node 只在**进程启动时**读一次代码。今天排查半天"改了怎么没反应",就是因为网关进程比代码改动更早启动。

- 改 `remote-gateway.js` → 必须杀掉进程重启
- 改 `mobile.css` / `mobile.js` → 刷新页面就行(网关每次请求实时读文件)

### 前端资源缓存已经解决,不用手动绕

`serveThemedIndex()` 已经会给注入的资源 URL 加 `?v=<文件mtime>`,文件一改 URL 就变,手机不会用到旧缓存。不需要再手动加时间戳。

### 用 Browser pane 在移动视口下验证

```
preview_start {url: "http://127.0.0.1:3098/"}
resize_window {preset: "mobile"}   // 375×812
```

然后用 `javascript_tool` 读实际计算样式/DOM 状态,用 `computer {action:"screenshot"}` 看效果。

**注意这个环境的已知限制**:CSS transition 有时会卡在 running 状态,导致 `getComputedStyle` 读到过渡中间值而不是终态。遇到读数不对劲时,先用 `el.getAnimations().forEach(a => a.finish())` 强制结束再读,别急着判定是 bug。

### 验证纪律

- 别只做代码审查就说"完成了",要真的跑起来看
- 涉及触摸手势的,用真实的 `Touch` / `TouchEvent` 序列,不要用 `.click()` —— 今天有个 bug 只在真实触摸序列下复现,`.click()` 测不出来
