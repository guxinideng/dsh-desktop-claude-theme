## 任务 1:触摸目标补到 44pt(优先级最高)

### 现状证据

实测页面上 16 个可交互元素,**14 个高度不足 44pt**:

```
搜索会话       28 × 28
视图选项       28 × 28
添加工作区     28 × 28
命令           28 × 28
访问模式       44 × 28
选择工作区     99 × 28
中文思考      106 × 28
选择模型      109 × 28
发送消息       34 × 34
设置          292 × 34
展开其余会话   292 × 28
新建会话      224 × 19   ← 最窄
iOS 建议最小   44 × 44
```

### 为什么是问题

鼠标指针是一个像素点,28px 完全够用——所以桌面版从没暴露过这个问题。手指的接触面积大约 9 毫米,28px 会频繁点不中、点到旁边,尤其底部工具栏那几个挨得很近的图标。

### 要做什么

把这些元素的**可点区域**扩大到至少 44×44。

**关键:扩大热区,不是把图标画大。** 视觉尺寸尽量保持现状,否则整个界面的比例会变。可用手法:

- 加 `padding` 撑开(注意可能影响相邻元素间距)
- 用 `::after` 伪元素做一个透明的扩展热区(`position:absolute; inset:-8px;`),视觉完全不变
- `min-height` / `min-width` 配合 flex 居中

伪元素热区是最不侵入的,优先考虑。但注意父容器不能是 `overflow:hidden`,否则热区被裁掉。

### 陷阱

- 底部工具栏是横向 flex,几个按钮挨得近。热区扩大后**可能互相重叠**,重叠区域的点击归属不确定。扩大前先量一下相邻元素的实际间距
- `.uV2eYG_row` 那一行已经有 `min-width: 0` 的收缩处理(第 405 行附近),动它的子元素尺寸时注意别破坏收缩逻辑
- 语音覆盖层 `.ds-mobile-voice-overlay` 盖在输入框上、有自己的手势判定,**不要动它的尺寸**
- 侧边栏的"新建会话"只有 19px 高,是最需要修的,但它在抽屉里,改动影响面小,可以放心做

### 验收

改完后用这段量一遍(在 Browser pane 移动视口下跑):

```js
(() => {
  const bad = [];
  document.querySelectorAll('button, a, [role="button"], input, textarea').forEach(el => {
    const r = el.getBoundingClientRect();
    if (r.width === 0 || r.height === 0) return;
    if (r.width < 44 || r.height < 44) {
      bad.push({
        label: (el.getAttribute('aria-label') || el.textContent || el.tagName).trim().slice(0, 20),
        w: Math.round(r.width), h: Math.round(r.height)
      });
    }
  });
  return { 仍不达标: bad.length, 明细: bad };
})()
```

注意:用伪元素做热区的话,`getBoundingClientRect()` 量的还是原尺寸。这种情况改用 `document.elementFromPoint()` 在按钮边缘外几像素处采样,确认能命中目标元素。

## 任务 2:动效参数统一

### 现状证据

时长散布在 6 个值,缓动几乎全是浏览器默认:

```
时长: 0.18s / 0.2s / 0.25s / 0.28s / 0.36s / 250ms
缓动: ease 7 处 / linear 2 处 / cubic-bezier 1 处(仅语音波形)
```

### 为什么读作"生硬"

各处动效彼此没有呼应,加上默认 `ease` 收尾偏突然,整体缺少同一套物理感。手机上因为动效多是全屏级的位移(抽屉滑入、面板切换),这种不一致比桌面更明显。

### 要做什么

定一套令牌放在 `mobile.css` 顶部,然后把散落的值收敛过去:

```css
:root {
  --ds-dur-fast: 0.18s;      /* 小元素状态切换:按压反馈、颜色变化 */
  --ds-dur-base: 0.25s;      /* 常规:面板、菜单 */
  --ds-dur-slow: 0.36s;      /* 大位移:抽屉滑入滑出 */
  --ds-ease: cubic-bezier(0.32, 0.72, 0, 1);   /* 主曲线,收尾平缓 */
  --ds-ease-out: cubic-bezier(0.16, 1, 0.3, 1); /* 进场,更明显的减速 */
}
```

曲线值可以自己调,上面是 iOS 风格的参考(起步快、收尾慢,接近真实物体减速),重点是**全局用同一套**。

### 陷阱

- **语音波形的动画不要动**(`ds-voice-pulse` / `ds-voice-breathe` / `ds-voice-shimmer`)。那套是刚做完、用户逐帧确认过的,时长和错峰延迟都是调过的
- 侧边栏的 `transition: left 0.25s` 可以换成令牌,但**不要把 `left` 改成 `transform`** —— 那会引发一个已知陷阱(transform 会让侧边栏成为内部 fixed 元素的定位基准,设置面板会错位),这条已经明确排除在本轮之外
- `prefers-reduced-motion` 下应该关掉或大幅缩短动效,如果文件里还没有这个处理,可以顺手加

### 验收

- 逐个打开侧边栏、设置面板、各个下拉菜单,确认动效仍然正常、没有变得过快或过慢
- 确认语音波形完全没受影响

## 任务 3:侧边栏可见入口

### 现状证据

```
toggle 按钮 display: none  (实测尺寸 0×0)
页头可见按钮: []           ← 空的
唯一入口: 左边缘 28px 内的滑动手势
```

原本的侧边栏开关按钮在移动端被隐藏了,打开侧边栏的唯一方式是从屏幕左边缘向右滑。页面上没有任何提示暗示这个手势存在。

### 要做什么

把这个按钮恢复显示,放在页头左侧,尺寸符合任务 1 的 44pt 标准。

### 重要:先搞清楚它为什么被隐藏

`mobile.js` 里有这么一段(第 56 行附近):

```js
return document.querySelector('button[aria-label="打开侧边栏"], button[aria-label="收起侧边栏"]');
```

这个按钮**被 mobile.js 用来程序化控制侧边栏状态**(`ensureDshExpanded` 会点它来纠正 dsh 的折叠状态)。隐藏它可能是刻意的——为了防止用户直接点到它、触发 dsh 自己的折叠逻辑,和抽屉的开合状态打架。

**所以这项要先确认:恢复显示后,用户点它会发生什么?** 是正常开合抽屉,还是会触发 dsh 的桌面折叠逻辑导致状态错乱?

在测试网关里实际点一下验证。如果确实会打架、需要 mobile.js 配合处理点击,**停下来报告**——那部分归 Opus。

### 如果确认可以安全显示

- 位置:页头左侧,和标题不冲突
- 尺寸:至少 44×44 的热区
- 图标:dsh 自己的图标就行,别自己画
- 注意 `.wSkVaW_header` 已经有 `padding-top: calc(12px + env(safe-area-inset-top))` 的安全区处理,按钮位置要考虑这个

### 这项是取舍不是缺陷

隐藏按钮换来了更干净的页头,滑动手势本身也符合手机直觉。**如果验证下来发现恢复显示的代价较大(需要动 JS、或者会引发状态问题),如实报告、不做也是合理选择。** 优先级低于前两项。
