灰化 + 扫光

一个等待态效果:把陈旧内容压暗,顶上跑一条光带,新内容到了就恢复。

这个效果原本用在 dsh 手机端的会话切换上,后来撤掉了 —— dsh 自己有一行 「载入历史…」,给那行字加动效就够了,再叠一层灰化是重复的,而且那行字 是准确的状态,灰化只是外部猜测。效果本身留在这里,换个场景还能用。

试一下

会话:等待态该怎么做
你加载要等一会儿,放个转圈的行不行?
助手转圈只说明"在转",不说明等的是什么。这里屏幕上已经有旧内容了 —— 更该做的是让人看出它是旧的。
你所以压暗?
助手压暗回答"这是陈的",光带回答"还在动"。两句话都要说,一个都不多。

怎么用

调用方拿到一个结束函数,数据到了就调它。这一点和原版不同:原版自己去猜 什么时候该结束,给 document.body 装了一个带 characterData 的全文档 MutationObserver, 回调里还要取一次整个容器的 textContent 做全文比对。切到一个正在 流式输出的会话时,每吐一个字都会触发一次全文遍历。谁发起等待谁就知道 什么时候结束,不需要猜。 

function showWaiting(pane, dimTarget) {
  dimTarget.classList.add('is-waiting');
  const sweep = document.createElement('div');
  sweep.className = 'sweep';
  pane.appendChild(sweep);

  let done = false;
  return function end() {
    if (done) return;   // 重复调用无害
    done = true;
    dimTarget.classList.remove('is-waiting');
    sweep.remove();
  };
}

// 用法
const end = showWaiting(pane, msgs);
const data = await fetchSomething();
end();

两条注意事项:

事项 原因
pane 需要是定位元素 扫光是 position: absolute,要贴在内容区顶边而不是整个视口。 给它 position: relative 即可 —— 但如果 pane 由框架 (React 等)管理,别去改它的 inline style,应当在自己的容器上加。
只动 opacity 合成层属性,不触发布局。加上扫光的 background-position, 整个效果在手机上几乎不花代价。别改成动 height 或 filter: blur()。

如果承载内容的节点由框架管理,只加 class、不往里面插节点 —— 扫光应该 append 到你自己的容器上。往框架管理的容器里塞 DOM 会和它的重渲染打架。
