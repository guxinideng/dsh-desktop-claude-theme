## 一、项目背景

`dsh-desktop-claude-theme` 是 DeepSeek Harness（`dsh`）的第三方桌面壳 + 换肤项目，核心原则**不 fork、不改 dsh 源码**，靠 CSS 覆盖 + DOM 脚本硬改。

本次会话的核心链路（已搭建并打通）：

```
手机浏览器 → https://deepseek.jiecaisongai.shop（Cloudflare → VPS 443 SNI 分流）
  → VPS nginx(4445, LE 证书) → SSH 反向隧道(autossh -R 127.0.0.1:8443)
  → Mac 上 remote-gateway.js(3090, HTTP + token) → 本地 dsh(3080, 单实例)
```

- 手机和桌面**共用同一个 dsh 实例**（实时同步）
- dsh 由 gateway 或桌面壳 spawn，带 `--trusted-host deepseek.jiecaisongai.shop`
- 手机端页面由 `remote-gateway.js` 拦截 index HTML，注入 `theme.css`/`mobile.css`/`mobile.js`（三个文件都在项目根目录）

## 三、关键诊断结论（重要）

### 1. 统计条的真实身份 = `FJxK0a_root`

用户一直说的"消息下面的用时/token 统计"，通过**手机真机 DOM 诊断**（mobile.js 把叶子文本结构 POST 到 gateway 的 `/__ds_theme/diag`）确认是：

```
类名: FJxK0a_root（在 composer 下方，uV2eYG_root 内）
内容: "74 轮 · 684 步"、"LLM 220m18s · 工具调用 59m46s"、
      "首 token 平均 11.2s · 101 tok/s"、"缓存命中 99%"、
      "输入 295M tok · 输出 567K tok"
```

**不是每条消息下面的统计**，而是**会话级 debug 统计条**（composer 下方）。

### 2. 该统计条其实早已有 CSS 隐藏规则

`mobile.css` 中已有：
```css
.FJxK0a_root { display: none !important; }
```
（注释为 "Per-turn debug stats (round/step count, LLM/tool timing) under the composer"）

**截图像素分析也证明**：用户最新截图（23.57.48）底部区域亮度 250+（纯米白，无统计文字）→ **CSS 隐藏已生效**。

### 3. "一直没生效"的根因 = iOS 独立模式强缓存

用户把页面"添加到主屏幕"（standalone 独立模式），该模式**强缓存**注入的 mobile.js/css，`no-cache` 响应头对独立模式无效。所有 JS 逻辑本地验证都通过，但手机一直跑旧文件。

**已加 cache-bust**（`?v=<文件mtime>`）解决——文件一变 URL 变，浏览器必拉新文件。

## 五、给接手者的建议

1. **先确认缓存**：让用户**删除主屏幕图标重新添加**，或用 Safari 无痕模式打开——cache-bust（`?v=`）已加，这是最后一块缓存拼图。
2. **统计条**：目标类名 `FJxK0a_root`，CSS 已有隐藏规则，核实真机是否生效即可。
3. **deepdiving**：先搞清楚它在哪个元素（可再用 `/__ds_theme/diag` 诊断端点，或让用户描述/截图定位）。
